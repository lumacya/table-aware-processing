# Контракт JSON

Документ описывает формат данных, который возвращает модуль `table_processor`. Это единая схема для всех способов вызова — через библиотеку, через FastAPI, через `run_demo.py`.

## Корневая структура

`ProcessingResult` — итоговый ответ на обработку одного файла.

| Поле | Тип | Описание |
|---|---|---|
| `filename` | `str` | Имя исходного файла, как его передал пользователь |
| `strategy` | `str` | Фактически использованная стратегия чанкинга: `row_based`, `semantic` или `auto` |
| `sheet_count` | `int` | Количество листов в файле |
| `total_rows` | `int` | Общее количество строк данных по всем листам |
| `total_chunks` | `int` | Общее количество чанков |
| `chunks` | `list[Chunk]` | Список чанков (см. ниже) |
| `sheets` | `dict[str, SheetMeta]` | Метаданные каждого листа — колонки, типы, профилирование, top_values, предупреждения. Ключ — имя листа |
| `warnings` | `list[str]` | Предупреждения уровня файла и листов |

## Структура `Chunk`

Один чанк — это фрагмент таблицы готовый к индексации в RAG-систему.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `str` | Уникальный идентификатор чанка. Формат: `{file_stem}__{sheet}__rows_{start}_{end}` для row_based или `{file_stem}__{sheet}__{group_col}_{group_val}` для semantic |
| `filename` | `str` | Имя файла (повторяется в каждом чанке для удобства индексации) |
| `sheet_name` | `str` | Имя листа |
| `strategy` | `str` | Стратегия по которой создан чанк: `row_based` или `semantic` |
| `row_start` | `int` | Индекс первой строки данных (0-based, без шапки) |
| `row_end` | `int` | Индекс последней строки данных включительно |
| `row_count` | `int` | Количество строк в чанке |
| `columns` | `list[str]` | Список имён колонок |
| `column_types` | `dict[str, str]` | Типы колонок: ключ — имя колонки, значение — тип (см. список ниже) |
| `source_ref` | `str` | Ссылка на диапазон в Excel-нотации, например `Лист1!A2:M51` |
| `content` | `str` | Текстовое представление данных в виде таблицы с разделителями `\|` |
| `summary` | `str` | Краткое описание для индексации: имя листа, колонки, диапазон строк, превью первых 3 строк, числовая статистика |
| `metadata` | `dict` | Дополнительные метаданные (см. ниже) |

### Содержимое `metadata`

Для row_based чанков:
- `chunk_index: int` — порядковый номер чанка в листе
- `chunk_size: int` — фактический размер чанка (может отличаться от запрошенного при `max_cells_per_chunk` или `max_bytes_per_chunk`)
- `oversized_row: bool` — присутствует если одна строка превысила `max_bytes_per_chunk` и составила отдельный чанк

Для semantic чанков:
- `group_column: str` — имя колонки по которой произведена группировка
- `group_value: str` — значение группы
- `row_indices: list[int]` — присутствует если строки группы несмежные (например группа разбросана по таблице)

## Структура `SheetMeta`

Метаданные одного листа. Возвращаются в поле `sheets` корневого ответа.

| Поле | Тип | Описание |
|---|---|---|
| `name` | `str` | Имя листа |
| `row_count` | `int` | Количество строк данных |
| `col_count` | `int` | Количество колонок |
| `columns` | `list[ColumnMeta]` | Метаданные каждой колонки |
| `header_rows` | `int` | Количество строк занятых шапкой (1 или 2) |
| `has_merged_cells` | `bool` | Найдены ли объединённые ячейки |
| `source_ref` | `str` | Ссылка на весь лист, например `Лист1!A1:S92123` |
| `warnings` | `list[str]` | Предупреждения уровня листа |

## Структура `ColumnMeta`

Метаданные одной колонки.

| Поле | Тип | Описание |
|---|---|---|
| `name` | `str` | Имя колонки |
| `dtype` | `str` | Тип колонки (см. список ниже) |
| `null_ratio` | `float` | Доля пропусков от 0.0 до 1.0 |
| `unique_count` | `int` | Количество уникальных значений |
| `sample_values` | `list[str]` | До 5 уникальных непустых значений |
| `top_values` | `dict[str, int]` | Top-5 значений с частотами для строковых и категориальных колонок |
| `min_value` | `float \| null` | Минимум для числовых колонок |
| `max_value` | `float \| null` | Максимум для числовых колонок |
| `mean_value` | `float \| null` | Среднее для числовых колонок |

## Типы колонок (`ColumnType`)

| Значение | Когда используется |
|---|---|
| `integer` | Целые числа без ведущих нулей |
| `float` | Дробные числа (поддерживается запятая как разделитель) |
| `datetime` | Дата с временем, например `2024-01-15 10:30:00` |
| `date` | Дата без времени, например `2024-01-15` или `15.01.2024` |
| `boolean` | Булевы значения: `true`/`false`, `да`/`нет`, `1`/`0` |
| `categorical` | Малое число уникальных значений относительно общего |
| `text` | Строки общего вида, включая идентификаторы (ИНН, КПП, ОГРН, артикулы) |
| `mixed` | Смешанные данные — часть значений числовая, часть строковая |
| `empty` | Колонка полностью пустая |
| `unknown` | Не удалось определить тип |

Идентификаторы (ИНН, КПП, ОГРН, ID, артикул и т.п.) определяются как `text` даже если состоят из цифр — это сохраняет ведущие нули и не порождает бессмысленную статистику min/max/mean.

## Стратегии чанкинга (`ChunkStrategy`)

| Значение | Когда применять |
|---|---|
| `row_based` | Простая нарезка по N строк |
| `semantic` | Группировка по значениям категориальной/датовой колонки |
| `auto` | Автовыбор: если есть подходящая категориальная колонка — `semantic`, иначе `row_based` |

## Параметры обработки

Параметры передаются в `process_file()` или как query-параметры `POST /process`.

| Параметр | Тип | Дефолт | Описание |
|---|---|---|---|
| `strategy` | `ChunkStrategy` | `auto` | Стратегия нарезки |
| `chunk_size` | `int` | `50` | Максимальное число строк в одном чанке |
| `max_cells_per_chunk` | `int` | `10000` | Защита от широких таблиц: эффективный размер = `min(chunk_size, max_cells // col_count)` |
| `max_bytes_per_chunk` | `int \| null` | `null` | Если задан — нарезка по байтам вместо строк. Строки не разрываются |

## Виды предупреждений

Поле `warnings` может содержать сообщения:

- `"Много пустых строк: N%"` — больше 20% пустых строк в листе
- `"Смешанные типы в колонках: A, B, C"` — колонки определились как `mixed`
- `"Подозрительные итоги в последней строке"` — последняя строка содержит числа в 3+ раза больше среднего по колонке (вероятно строка «Итого»)
- `"Обнаружены объединённые ячейки"` — на листе есть merged cells
- `"Стратегия X недоступна, использована Y"` — пользователь явно запросил стратегию которая не сработала
